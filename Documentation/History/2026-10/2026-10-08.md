# 2026-10-08

## Where an opening's time went

A book opened onto empty pages, with the text arriving after the cover had finished turning. Timed on
the simulator from the tap, with the bundled book part read:

| | first sheet cut | opening ends |
| --- | --- | --- |
| title page | 38 ms | 884 ms |
| part read, same process | 324 ms | 866 ms |
| part read, fresh process | 1734 ms | 883 ms |

Everything before the chapter's text is in hand takes under 50 ms: building the screen, the store,
the chapter's content. Inside the cutting, for a chapter of 938 paragraphs and 75 pictures:

| | fresh process | same process |
| --- | --- | --- |
| pictures read | 1604 ms | 201 ms |
| text set | 42 ms | 39 ms |
| first paragraph composed | 28 ms | 27 ms |

`ChapterLayout.prepare` read every picture in the chapter before it set a line, because a plate's
depth has to be known to set the line it stands on. Reading meant decoding, shrinking and looking at
every pixel to tell colour art from line work. The same-process figure is high too: the cache held 64
pictures and the chapter has 75, so eleven were read again every time.

Only a picture's size is needed to set a page. `BookImages.prepare(sources:)` now reads that off the
file's header and leaves the pixels until a page that shows the picture is made ready or drawn.

| | first sheet cut, before | after |
| --- | --- | --- |
| part read, same process | 324 ms | 113 ms |
| part read, fresh process | 1734 ms | 138 ms |

A phone is slower than the Mac the simulator runs on, and these weren't taken on one.

## The back of the leaf, blank

Shut before any page was turned, a book showed blank paper on the back of its cover where the page
before should be. `OpeningBook` borrows that page's drawn layer contents, and the contents were
there, but the strips showed nothing. A page that has been on screen, after a turn, was fine. Marking
the layer for display and drawing it again as it's handed over fixes it: the same page shows its
text with the redraw and nothing without it. Why a layer that has only stood at no opacity hands over empty contents wasn't found.

## Driving the reader from a UI test

On the Duo simulator a tap on the reader's close button waited 23 seconds and then landed on the
page, turning it. A drag down the page shuts the book reliably, and `press(forDuration:thenDragTo:
withVelocity:thenHoldForDuration:)` holds it half shut for a screenshot from the host.
