## A page with four lines of room left at its foot

Reported mid-chapter: 23 lines, and 84pt of the 760pt measure empty under them. Measured off the
screenshot, the pitch is 29.6pt: the 26.6pt line that setting gives, plus the leading pegged at its
3pt cap. So the lines were set at the setting in force, and the page had too few of them.

Cut again from the report's own chapter and setting, the same first line takes 29 lines and fills the
measure to the point, forwards and from behind alike. The same text comes to 23 lines in any measure
from 600pt to 670pt. The window less its bands twice over is 664pt, which is the trap the page is
built to avoid: a size read from the layout rather than from the window. Nothing in the report says
which path did it this time, and the reader changed no setting.

A sheet that settles with a page a line or more short mid-chapter is cut again now, since a page cut
against the measure in force never stands short. The debug report writes `layout.txt` as well: the
measure each page on screen was cut against beside the one the reader asks for, the window and the
sheet, and the last sixty cuts, so the next page like this says where its measure came from.

## The background sweep did nothing from a cold launch

The app registered and scheduled the daily refresh, but when iOS launched it into the background to
run it, the session was still `.restoring`: only the root view's task restores it, and iOS builds no
view on such a launch. The run saw nobody signed in and returned. It worked only when the app had
been suspended rather than terminated. The run now restores the session itself.

Two smaller gaps came up in the same check. Only the profile screen asked for the badge permission,
so a reader who never went there got no icon badge at all; the library asks before its first sweep
instead. And the library read its per-book counts back only on a store refresh, so whatever a
background run found stayed hidden until something else redrew the shelf. Coming to the foreground
now triggers that refresh.
