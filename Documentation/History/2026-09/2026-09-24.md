# 2026-09-24

## A Litres sign-in that never took

A TestFlight tester signed in to Litres, pressed "Bring my books across" and got "The session ran out.
Sign in again." straight away. The screen then offered no way to sign in again.

What the code did:

- The web view took the first jar holding `SID` and `supersid` as the session and closed the sheet. A
  guest `curl` of `/my-books/` gets `supersid` in the first reply from behind DDoS-Guard, so a visitor
  carries at least half of a session before signing in. Whether the site's scripts also give a guest
  `SID` wasn't checked.
- The web view's jar is the default, persistent one, so a stale session left in it from an earlier
  visit was taken on the first page load.
- A failed run kept the session, so `isSignedIn` stayed true and only "Bring my books across" showed.
- The client mapped every 401 and 403 to `.unauthorised` before checking the service's own header, so
  a 403 from DDoS-Guard read as an expired session.

What changed:

- A session is adopted only once its context names a reader and `/users/me/arts` answers signed in.
- `LitresClient.refusal(of:host:)` rules out the guard before it believes a refusal.
- A refused session is dropped, "Sign in to Litres" comes back, and the next sign-in clears the
  session cookies from the jar first.
- `LitresTrail` keeps the sign-in and the run in memory through a `TracedMemoir`, which brought the
  Memoirs package into the app. "Share Litres login logs" mails the scrubbed trail as a zip to
  bugreport@lonelybytes.com.

Not yet known: whether a guest's context carries a `user_id`, and whether a guest gets 200 from
`/users/me/arts`. The trail records the context's field names and the reply, so the tester's next
attempt should answer both.

## Every log through Memoirs

The rest of the app's logging moved off `OSLog`'s `Logger` too. Each type that logged keeps its old
category as a `TracedMemoir` label, over `AppMemoir.root` in the app or a `rootMemoir` in
`AuthorToday`, `BookRenderer` and `BookStorage`, which now depend on Memoirs. Every root is an
`OSLogMemoir` under the old subsystems, so Console filters still match. `LitresTrail` writes through
`AppMemoir.root` as well.
