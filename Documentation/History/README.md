# History

One file per day, in a directory per month: `YYYY-MM/YYYY-MM-DD.md`. Each entry says what was built
that day, what was tried and abandoned, and what was measured.

This is the only append-only part of the documentation. Everything under `Documentation/` proper
describes how the app works now and is rewritten rather than added to.

An entry is worth writing when the day produced something that isn't obvious from the code: a
constraint discovered, a measurement taken, an approach that failed and why. Skip the diary.
